# Follow-up implementation review — 2026-10-20

This review adds failure and boundary checks beyond the original successful build.
It preserves the existing site's visual language and imports no UI from the old project.

## Corrected findings

- Repeated search parameters caused a public 500; fractional/infinite page numbers
  could reach database pagination. Inputs now normalize to bounded scalar values.
- CMS project pagination linked to `/blog`, and `/work` ignored its page parameter.
  New project records now paginate within `/work`; empty later pages offer a way back.
- Saving new content left the editor without its saved ID. Subsequent saves now
  update that record, expose private preview, and refresh stored revisions.
- Approved English could be incomplete. Every approved public translation now
  requires a summary and body; unfinished unapproved English remains optional.
- Media and its audit log were separate writes. They now commit together, failed
  uploads remove their own file, and storage failures return 503 rather than 422.
- Policy CMS SEO was ignored, policy breadcrumbs linked to a missing `/pages`,
  and unavailable policy translations could render an empty error response.
- Language switching linked to missing translations. Unavailable translation
  switches are now omitted; published locales remain the source for hreflang.
- `noIndex` also hid published content from its listing. It now controls indexing
  and sitemap inclusion while keeping that content available within the site.
- Redirect source URLs could remain in the sitemap. Sitemap generation excludes
  them; paginated listings now have their own canonical page URLs and filtered
  search results are noindex.
- A delayed inquiry retry could be rejected after a receipt already existed.
  Valid retries now return that original receipt before new-submission limits.
- Protected admin pages now enforce their own sign-in requirement, independently
  of their parent layout, rather than asserting that a staff object exists.
- CI previously built the Docker runner without starting it. The container job
  now runs isolated PostgreSQL/application containers, exercises real HTTP writes,
  checks non-root execution, restarts with persisted media, and rehearses recovery.
  Manual image publication requires both validation and container checks to pass.

## Verification

- Lint, TypeScript and production build.
- 29 unit tests and 4 dedicated-database integration tests.
- 56 public routes, 285 referenced assets, 72 internal links and 36 locale documents.
- Expanded production HTTP scenarios: duplicate parameters; anonymous page guards;
  13 project fixtures across two pages; noindex versus visibility; policy metadata;
  missing translation switches; delayed inquiry retry; transactional media rollback
  under an intentionally failing database audit trigger; existing publication,
  concurrency, auth, redirect, form and upload checks.
- Manual browser verification: create a local draft, save again with a changed
  title, confirm one record, the same ID and a working private-preview link.
- Ubuntu container runtime and backup rehearsal run in the GitHub `container` job.

timers, monitoring and final contact/social destinations remain deferred as requested.
