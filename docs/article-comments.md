# دیدگاه‌های مقاله

دیدگاه‌ها در صفحهٔ هر مقاله، پیش از مقالات مرتبط قرار دارند و در فارسی و انگلیسی جدا نگه داشته می‌شوند. بازدیدکننده بدون حساب کاربری، نام نمایشی و متن دیدگاه را وارد می‌کند. ایمیل اختیاری است و در خروجی عمومی یا HTML مقاله قرار نمی‌گیرد.

## مدیریت

در `/admin/comments` با نقش `ADMIN` وارد شوید. فهرست ابتدا دیدگاه‌های «در انتظار تأیید» را نشان می‌دهد. جست‌وجوی نام، متن و عنوان مقاله، فیلتر وضعیت، تعداد موارد منتظر و صفحه‌بندی در دسترس است.

- وضعیت «تأییدشده» به معنی نمایش عمومی است.
- «در انتظار تأیید»، «ردشده» و «هرزنامه» عمومی نیستند؛ تغییر این وضعیت‌ها برگشت‌پذیر است.
- پاسخ رایکد اختیاری است و فقط همراه دیدگاه تأییدشده منتشر می‌شود.
- برای برداشتن دیدگاه از سایت، وضعیت را به «ردشده» برگردانید. در بارگذاری بعدی صفحه یا API دیگر نمایش داده نمی‌شود.
- تغییر وضعیت و پاسخ، با شناسهٔ مدیر در `AuditLog` ثبت می‌شود. ویرایش هم‌زمان با بررسی `updatedAt` از بازنویسی تصمیم مدیر دیگر جلوگیری می‌کند؛ در صورت تعارض فهرست را تازه کنید.

## ذخیره‌سازی و API

مهاجرت `20261102120000_article_comments` جدول `Comment` و چهار وضعیت آن را اضافه می‌کند. پیش از اجرای نسخهٔ جدید، `npm run db:migrate` و `npm run db:generate` اجرا شوند؛ فرایند موجود CI/CD مهاجرت‌ها را اعمال می‌کند.

- `POST /api/comments`: فقط برای مقالهٔ قابل‌نمایش با ترجمهٔ تأییدشده؛ وضعیت همیشه `PENDING` است، حتی اگر درخواست وضعیت دیگری بفرستد.
- `GET /api/comments?articleId=UUID&locale=fa&page=1`: حداکثر ۱۰ دیدگاه تأییدشده در هر صفحه؛ فقط نام، متن، پاسخ، تاریخ و شناسهٔ عمومی را برمی‌گرداند. مقالهٔ پیش‌نویس، آرشیوشده، زمان‌بندی‌شده برای آینده یا ترجمهٔ تأییدنشده در دسترس نیست.
- `GET/POST /api/admin/comments`: نیازمند نشست مدیر. ویرایشگر مجوز بررسی دیدگاه‌ها ندارد.

متن‌ها با React به‌صورت متن ساده نمایش داده می‌شوند؛ HTML کاربر اجرا نمی‌شود. متن و پاسخ حداکثر ۳۰۰۰ نویسه، نام حداکثر ۸۰ نویسه و بدنهٔ درخواست عمومی حداکثر ۲۰ کیلوبایت است. بررسی مبدأ، honeypot، زمان تکمیل فرم و محدودیت ۸ ارسال در ۱۵ دقیقه فعال است. مانند فرم تماس، در Ubuntu پشت پراکسیِ قابل‌اعتماد، `TRUST_PROXY=true` و پیکربندی ارسال/بازنویسی صحیح هدر IP لازم است؛ بدون آن محدودیت مشترک برای مبدأ محلی اعمال می‌شود. IP خام ذخیره نمی‌شود.

کلید درخواست، تکرار ناشی از تلاش مجدد را خنثی می‌کند. اثرانگشت HMAC متن، نام، ایمیل، مقاله، زبان و روز نیز ارسال یکسان با کلید تازه را در همان روز ادغام می‌کند. تکرار هیچ‌گاه وضعیت بررسی یا پاسخ قبلی را بازنشانی نمی‌کند. ایمیل برای اطلاع‌رسانی خودکار استفاده نمی‌شود و این نسخه اعلان ایمیلی ندارد.

## اعتبارسنجی

`npm run test:local` آزمون‌های یکپارچه را فقط روی پایگاه دادهٔ اختصاصی تست اجرا می‌کند: انتظار تأیید، جلوگیری از تکرار، حریم خصوصی، مجوز مدیریت، پاسخ و لغو تأیید، تعارض ویرایش، محدودیت ارسال و صفحه‌بندی. هیچ دادهٔ واقعی برای اجرای این آزمون‌ها حذف نمی‌شود.
